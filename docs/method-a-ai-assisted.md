# 方法 A：AI 辅助版（省事，但要会把关）

> 适合：不打算啃原理，想尽快跑通；会复制粘贴、能看懂报错、愿意为每一步负责。
> 不适合：完全不想动手；或者把 AI 的输出直接当权威。

---

## 先说清楚 AI 能做什么、不能做什么

| AI 擅长 | AI 不擅长（会翻车） |
|---|---|
| 把大任务拆成小步骤 | **不知道你的真实网络环境**（设备型号、Portal 实现、信道情况） |
| 生成命令、写脚本、解释报错 | 会**编造**不存在的参数、接口名、包名 |
| 根据你贴的日志推断原因 | 一旦信息不足就会**自信地猜错** |
| 批量改写配置 | 危险操作（刷机、停服务）判断不了"现在能不能做" |

**所以分工是：AI 负责想和写，你负责执行和验收。**

---

## 铁律（先背下来再开始）

1. **任何 `mtd write`、刷 Bootloader、`sysupgrade`、`/etc/init.d/* stop` 命令，
   必须你亲眼确认过参数，并且知道自己怎么救回来。**
   本项目就出过一次事故：AI 判断"停掉 UA3F 就能排除故障"，
   结果停掉后整个局域网瞬间断网，而 AI 在远端根本没有恢复通道。
2. **AI 说"应该可以了"不算数，只有实测数据算数。**
   每次都要求它给一条**可验证的命令**（ping、curl、nft 计数、重传率），
   看到输出再进下一步。
3. **一次只改一个变量。** 同时改两个地方，出问题就分不清是谁的锅。
4. **动手前备份。** 刷机前备份整片 flash 和 EEPROM；
   改配置前 `cp /etc/config/xxx /etc/config/xxx.bak`。
5. **别把真实密码贴给 AI。** 用占位符，让它生成带占位符的脚本，你自己填。

## 操作流程（按顺序把下面每段丢给 AI）

> 用法：复制一段 → 把 `<尖括号>` 里的内容换成你的实际情况 → 发给 AI。
> 拿到命令后**先问一句**："这条命令会改变什么？出问题怎么回滚？"

### 第 1 段：摸底

```
我在把一台小米 AC2100（MT7621，128MB RAM/128MB NAND）刷成 OpenWrt 做校园网共享。
现在路由器的状态是：<已刷 Breed r1416 / 已经是 OpenWrt xx.xx / 还是原厂>。
请给我一组只读命令，用来确认：CPU/内存/闪存、当前固件版本、无线芯片型号、
WAN/LAN 口对应关系、是否已有 IPv6。不要给任何写操作。
```

### 第 2 段：刷机

```
我要从 Breed 刷 OpenWrt 24.10 到这台 AC2100。
已知：Breed 在 192.168.1.1，按 Reset 上电可进入；设备在 OpenWrt 里的型号是
xiaomi_mi-router-ac2100。
请告诉我：
1) Breed 里「闪存布局」应该选哪个；
2) 要准备哪几个文件、分别刷到哪个分区；
3) 刷完起不来的最常见原因是什么、怎么预防；
4) 哪一步绝对不能断电。
每步给出「失败时的现象」和「回滚方法」。
```

### 第 3 段：接入校园网（最关键）

```
我校校园网是：开放 SSID + 网页认证（Portal）。
未认证时，浏览器访问任意 http 站点会被重定向到
http://<认证服务器IP>/eportal/index.jsp?wlanuserip=...&mac=...&t=... 这样的地址。
我的路由器要自己作为一台设备连上这个 WiFi 并完成认证，然后开热点给宿舍用。

请按这个顺序帮我：
1) 怎么让路由器的 5G 射频进入客户端（STA）模式连这个开放 SSID；
2) 怎么判断这个 Portal 是锐捷 eportal、深澜还是 Dr.COM；
3) 如果是锐捷 eportal，怎么在不抓包的前提下，从它的 JS 里找出登录接口和参数；
4) 给我一个带失败退避（避免密码错把账号撞锁）的登录脚本骨架。
```

### 第 4 段：防共享检测

```
路由器已经能上网了。现在要防止学校通过 User-Agent / TTL 识别出
"一个账号后面挂了多台设备"。
我打算用 UA3F（https://github.com/SunBK201/UA3F）。
请告诉我：
1) 它需要哪些内核模块和依赖；
2) REDIRECT 和 TPROXY 两种模式的区别，我这台 MT7621 应该用哪个、为什么；
3) 装完之后怎么验证 UA 真的被改写了（要一条能直接看到结果的命令）；
4) 有没有已知的坑。
```

### 第 5 段：排错（把现象和数据一起给）

```
现象：<例如：网页能打开，但所有游戏和加速器都连不上，测速正常>
我已经测到的数据：
- 从路由器 ping 公网：<结果>
- 从电脑 ping 公网：<结果>
- nft list ruleset | grep -c <STA接口名>：<结果>
- UA3F 的 fd 数：<结果>
- 链路重传率：<结果>
请按可能性从高到低列出原因，每条给出**验证命令**，不要直接给修复命令。
```

## 验收清单（每完成一阶段，逐条打勾）

```sh
# 1. 基础连通
curl -s -o /dev/null -w "%{http_code}\n" http://www.baidu.com          # 期望 200
curl -s -o /dev/null -w "%{http_code}\n" http://<局域网某IP>            # 期望能通

# 2. 全协议转发（UDP/ICMP 最容易漏）
ping -c 3 223.5.5.5                                                     # 期望通
nft list ruleset | grep -c <STA接口名>                                  # 期望 > 0

# 3. 认证自愈
/usr/bin/portal-login status                                            # 期望 ONLINE
# 手动踢自己一次，看 2 分钟内是否自动回来

# 4. UA 改写
curl -s http://httpbin.org/user-agent                                   # 期望不是原始 UA

# 5. 设备数
# 登录学校自助服务页，确认只占 1 个名额
```

## 这个项目里，AI 实际帮上忙和帮倒忙的地方

**帮上忙：**

- 把"锐捷 eportal 怎么登录"这种模糊问题，拆成"先抓重定向 → 再读 JS 找接口 → 再调 pageInfo"三步
- 从 55KB 的登录页 JS 里定位到 `AuthInterFace.js` 和 `InterFace.do?method=login`
- 根据 `ping` 的 min/avg/max 分布，推断出"不是丢包而是排队"
- 把一堆散乱的实测数据整理成对比表，快速定位"DNS 指向远处 CDN"这个原因

**帮倒忙（真实发生）：**

- 判断"停掉 UA3F 就能验证它是不是元凶"→ 停掉后全网断，且远端无法恢复
- 一开始认定"学校封了 UDP"→ 实际是我们自己防火墙规则没匹配到 WiFi 出口
- 试图用 nft mark 把 HTTPS 排除出 UA3F → 直接把 HTTPS 打挂

**共同点：AI 在"信息不足"时会自信地给出错误结论。**
所以**永远要求它先给验证命令，看到数据再改**。
